# Pull Request Checklist

Use this checklist on every PR to ensure consistency and quality.

- [ ] PR links to an issue or project card (if applicable) and includes acceptance criteria
- [ ] Title clearly describes the change and scope
- [ ] PR size is reasonable (aim <= 400 lines of code)
- [ ] Automated CI checks pass (unit tests, linting, security scans)
- [ ] New unit/integration tests added where appropriate
- [ ] Documentation updated (docs/ or README) as needed
- [ ] All TODOs justified or tracked in issues
- [ ] At least one approval from a reviewer (per team policy)
- [ ] Merge strategy noted (squash/merge/rebase) and any release notes drafted

Notes:
- Small, focused PRs reduce review time and risk.
- If the PR touches public or shared APIs, add a migration note if needed.
